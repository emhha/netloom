# dirscan

`dirscan` 是建立在 Netloom 网络运行时上的目录扫描包，提供显式字典、响应过滤、wildcard 检测、链接提取及目录递归。调用方负责扫描授权；包不提供持久化或后台服务。字典配置与来源见[字典说明](wordlists/README.md)。

## 递归与扫描根

- `BaseURL` 的路径是固定扫描根。例如 `https://example.com/app/` 的根为 `/app/`。
- `RecursionDepth` 始终相对这个固定根计算，不会随当前父目录重置。根的深度为 0，`/app/a/` 为 1，`/app/a/b/` 为 2；0 表示不限制深度。
- 上限同时作用于普通、深层、强制递归和 Crawl 发现的目录。深度控制的是继续扫描哪些目录，不禁止字典自身包含多层路径。
- Crawl 解析相对链接与同主机绝对链接；提取出的 URL 路径不会再次拼接当前目录。扫描根之外的链接不进入 Crawl 队列；路径前缀相似不代表位于根内，例如 `/application/` 不属于 `/app/`。

## 并发、背压与聚合

- `Threads` 控制每目录请求窗口，默认 30；设置 1 可串行派发。窗口同时包含在途请求和已完成但尚未按序聚合的响应，最多 `Threads` 个，不会因队首慢请求而无限缓存后续正文。队首阻塞时允许其他 worker 空闲，这是保序与窗口上限的取舍。
- 固定数量 worker 只负责调用 `Engine.Send`；单一协调器按派发顺序执行 wildcard 分类、字段计算、过滤、正文去重、结果收集及 Crawl/递归入队。目录之间仍串行，每目录的两个 wildcard 校准请求也在工作请求前串行完成。
- Engine 的全局和同主机并发上限均设为最终 `Threads`，不会额外受默认同主机 10 个槽限制；仍遵守 Engine 默认 150 次逻辑请求/秒的准入限流及传输保护。重试可能增加实际网络尝试数。自动模式在准备阶段可能下调线程数；本包不另设 SmartSkip 开关。
- 已发现的 Crawl 链接优先于**尚未派发**的字典项，不抢占已派发请求。网络到达顺序不等于派发顺序；并发 Crawl 的发现时机会影响后续派发，不能保证不同运行的完整结果顺序一致或完全等同串行扫描。
- `MaxConsecutiveErrors` 默认 8，按派发顺序统计 `Send` 错误、nil 响应及 `Response.Error`，仅真正成功才清零。达到阈值后永久停止该目录派发、取消并等待在途请求；最多已有 `Threads-1` 个后续任务被接纳。已完成的成功响应仍经过正常过滤/去重，但不会重启该目录派发。此局部停止不取消整次扫描，已排队的其他目录仍可继续。
- `MatchWords`/`MatchLines` 和 `FilterWords`/`FilterLines` 使用聚合时从正文计算的真实计数，不读取未初始化的零值。
- 窗口只约束请求与重排响应，不是整次扫描的硬内存预算；字典、发现队列、去重集合和结果仍随输入/发现量增长。运行期间调用方不得修改配置及其 map/slice。

## 取消与部分结果

`Run(ctx, cfg)` 的 context 取消会传播至请求。`MaxTime` 为整次扫描设置总体 deadline（包含准备阶段），更早的调用方 deadline 仍然生效。

取消或到期时停止新任务派发，取消并等待全部已接纳请求退出，期间按派发顺序聚合已成功完成的响应（仍应用正常过滤/去重）；不会因 context 结束而丢弃已完成的乱序响应。返回**已完成的结果和非 nil 错误**，而不是将部分结果视为扫描成功完成。调用方可使用 `errors.Is(err, context.Canceled)` 或 `errors.Is(err, context.DeadlineExceeded)` 区分中断原因；没有完成任何发现时结果可以为空。请求失败或被取消时，不会将该请求作为成功结果加入列表。

## 回归验证

```sh
go test ./dirscan
go test -race ./dirscan
```

扫描循环回归通过私有 fake engine 和 channel 屏障验证并发重叠、窗口上限与乱序聚合、错误阈值、实际递归与 Crawl 入队、固定非根路径的深度边界、根外链接拒绝，以及取消/deadline 时在途退出与部分结果保留。不访问外部网络，也不关闭生产拨号保护；这些测试不代表真实网络吞吐或性能验收。
